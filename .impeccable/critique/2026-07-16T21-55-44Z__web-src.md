# ChroniCare Visual Prototype Critique

## Design Health Score — Nielsen

**23/40 — fondasi aman dan cukup koheren, tetapi belum terasa seperti interface yang selesai diarahkan.**

| Heuristic | Skor | Bukti utama |

## Anti-pattern dan AI-slop verdict

ChroniCare **tidak masuk AI-slop dekoratif yang kasar**. Tidak ada gradient text, glassmorphism, hero SaaS, bento/card grid dekoratif, over-rounding, neon treatment, atau random illustration. Detector menghasilkan **1 warning dan 0 error**; warning `font-family: Arial` adalah false positive karena hanya dipakai pada facsimile dokumen sintetis, bukan identitas aplikasi.

Namun interface masih mudah terbaca sebagai hasil generasi AI yang “aman”: wireframe yang diberi token. Tanda utamanya adalah grammar komposisi yang terus berulang (`judul → divider → list`), semua elemen memperoleh visual weight yang hampir sama, warm canvas dipakai hampir di semua mode, whitespace desktop tidak mempunyai fungsi, informasi penting dikecilkan menjadi metadata 10–13px, dan serif dipakai sebagai shortcut untuk memberi karakter. Patient dan Caregiver berbeda density, tetapi belum berbeda cukup kuat dalam cara mengarahkan perhatian dan emosi.

## Hal yang sudah bekerja

1. Safety language dan trust boundary kuat. SOS tidak mengklaim dispatch, OCR mempertahankan original-first dan pending/confirmed, serta Faskes tidak mengklaim data live atau penerimaan BPJS.
2. Fondasi mode sudah benar. Patient narrow, sequential, dan mobile-first; Caregiver lebih padat dengan sidebar, Patient context, dan operational sections.
3. Core journey dapat diselesaikan dan feedback dasarnya nyata. Tidak ditemukan horizontal overflow pada route yang diuji. Invalid code, check-in success, safe fallback, emergency escalation, upload error, OCR status, switch masking, dan SOS handling mempunyai visual state.
4. Semantic status umumnya tidak color-only; focus ring 2px/3px terlihat pada link dan button umum.

## Lima masalah paling berdampak

### P1 — OCR belum menjadi comparison tool yang dapat dipercaya

Pada 390×844, review OCR memiliki tinggi sekitar 2291px. Extraction baru dimulai pada Y≈1149 dan keputusan pada Y≈2060. User melihat seluruh dokumen, lalu seluruh draft, lalu action; hubungan evidence-to-field hilang dan working memory menjadi alat perbandingan. Ini bertentangan dengan kontrak dua tab eksplisit pada mobile. Di desktop, split original/extraction sudah benar, tetapi keputusan masih jatuh di bawah viewport dan pane belum memiliki independent scroll. Tombol zoom 40×40 inert, dan field OCR menghapus global focus ring melalui `outline: none`.

Perbaikan: mobile memakai tab `Dokumen asli` dan `Hasil ekstraksi`, dengan Patient/document/status/provenance di luar panel. Tambahkan progress review dan `Lihat pada dokumen` per field. Desktop memakai fixed-height 45/55 workspace dengan independent pane scroll dan correspondence highlight. Decision region tetap in-flow namun mudah dijangkau, tanpa menutup focus/keyboard.

Command: `$impeccable layout` → `$impeccable adapt` → `$impeccable polish`.

### P1 — Patient typography dan touch sizing melanggar accessibility contract

DESIGN.md menetapkan Patient body minimum 18/28 dan target 48×48. Implementasi masih memakai 12–17px pada metadata, reminder, chat, dan SOS; tombol check-in/SOS 44px; brand 34px; exit 32px; back link 44px. Hidden radio 13×13 bukan masalah karena label tile berukuran 56–70px—itu false positive.

Perbaikan: naikkan Patient reading/safety/control copy ke 18/28; pertahankan hierarchy lewat weight, color, dan spacing. Semua Patient task target—termasuk back, exit, brand-home, dan SOS—memiliki hit box minimum 48px. Caregiver operational body mengarah ke 16/24 dan metadata 14/20.

Command: `$impeccable typeset` → `$impeccable adapt` → `$impeccable polish`.

### P1 — SOS caregiver mengandung system-status contradiction dan operational truth tidak lengkap

Direct `/caregiver/sos` saat state IDLE tetap menampilkan `SOS Maya Pratama`, `diminta baru saja`, `Menunggu caregiver menangani`, dan `SOS dicatat`, sementara tombol disabled dan global alert tidak ada. Saat event aktif, persistent banner hanya menunjukkan Patient/lokasi/waktu relatif; visible connection, audio state, exact/fresh time, dan distinction `handled ≠ resolved` belum ada.

Perbaikan: gate detail berdasarkan state. IDLE menampilkan `Tidak ada SOS aktif` tanpa Patient/event timestamp. ACTIVE/HANDLING/HANDLED/CONFLICT baru menampilkan event facts. Alert memakai dua level: `SOS keluarga aktif — Maya Pratama`, lalu `Tercatat 08.42 · Dashboard terbuka · Suara nonaktif`. Handled state menyatakan `Koordinasi diambil Dimas`, bukan situasi selesai.

Command: `$impeccable harden` → `$impeccable clarify` → `$impeccable layout` → `$impeccable polish`.

### P2 — Hierarchy dan mode differentiation terlalu datar

Caregiver dashboard mengulang Patient context pada topbar dan content band, lalu memakai divider seragam. Latest change dan `Tindakan berikutnya` tidak memperoleh weight yang cukup berbeda; links hanya sekitar 19.5px tinggi. Patient warmth terutama berasal dari beige canvas dan greeting, bukan dari pola interaksi khas. Access desktop memakai split-auth generik dengan whitespace pasif. Serif Georgia pada check-in/SOS menjadi satu-satunya “signature”, padahal DESIGN.md melarang display/serif family pada UI aplikasi.

Perbaikan: dashboard memakai satu compact persistent Patient header, kemudian dua scan anchor yang jelas: `Terbaru` dan `Perlu tindakan`. Patient home memakai satu functional `Hari ini` anchor untuk check-in state + next reminder, disusul entry chat/SOS yang flat. Access dipadatkan pada satu vertical axis yang purposeful. Karakter dibangun lewat scale, rhythm, and information grouping—not a second font.

Command: `$impeccable bolder` → `$impeccable layout` → `$impeccable typeset` → `$impeccable colorize`.

### P2 — Orientation, provenance, dan demonstrable states belum tuntas

Tidak ada `aria-current` atau active-route marker pada Patient/Caregiver nav. Patient switcher belum memiliki interaction model dialog yang lengkap. Dashboard links, Faskes filters 36px, disclosure summary 16.5px, OCR zoom 40px, dan SOS controls 40px berada di bawah target caregiver 44px. Beberapa small blue links memiliki contrast sekitar 4.38:1 pada canvas dan 4.21:1 pada info surface. OCR fallback dan SOS conflict ada di state/component tetapi tidak dapat dicapai lewat browser flow. Faskes source per-result ada di disclosure; review date baru muncul setelah filters; direct-confirm limitation tidak diulang setelah list.

Perbaikan: active nav dengan `aria-current`, proper popover/dialog behavior, 44px hit areas, verified semantic link token, visual-only fixture entry untuk OCR fallback/SOS conflict, dan provenance strip Faskes sebelum filters. Source/review tetap terlihat per row dan direct-confirm instruction diulang setelah results.

Command: `$impeccable adapt` → `$impeccable colorize` → `$impeccable harden` → `$impeccable polish`.

## Mengapa desain masih terasa basic

1. Satu grammar layout dipakai hampir di semua layar. Perubahan konten tidak menghasilkan perubahan composition yang bermakna.
2. Scale hierarchy terlalu sempit: heading cukup besar, tetapi hampir semua hal di bawahnya turun menjadi small metadata. Akibatnya whitespace terasa kosong, bukan tenang.
3. Borders dan white surfaces melakukan terlalu banyak pekerjaan. Hampir tidak ada emphasis yang datang dari proportion, alignment, grouping, atau controlled color field.
4. Signature moments belum dibangun pada task yang seharusnya paling khas: check-in closure generik; OCR menjadi form panjang; handled SOS ambigu; caregiver next action terlalu ringan.
5. Patient dan Caregiver dibedakan oleh density, belum oleh behavior. Patient belum cukup reassuring melalui pacing/closure; Caregiver belum cukup operational melalui recency, provenance, dan immediate action.
6. Serif dipakai sebagai dekorasi untuk check-in quote/SOS, bukan karena kebutuhan informasi. Itu menutupi masalah hierarchy tanpa menyelesaikannya.

## Persona red flags

### Patient mobile yang lelah atau terdistraksi

- Header dua baris sekitar 112px menghabiskan prime space; `Keluar dari demo` hanya 32px tinggi.
- Safety/support copy sering 13–17px, di bawah kontrak 18px.
- Patient chat membuka blank transcript well; suggestion terakhir dan composer terdorong mendekati/di bawah fixed nav.
- SOS confirmation masih menampilkan routine bottom nav dan demo exit sehingga fokus sensitif terpecah.
- Check-in success tidak merangkum jawaban yang baru disimpan, sehingga closure lemah.

### Caregiver di bawah tekanan waktu

- Tanpa active nav, lokasi harus diinfer dari H1.
- Latest state, provenance, dan next action membutuhkan pembacaan metadata kecil, bukan scan tiga detik.
- OCR mobile meminta memori; desktop decision berada di bawah fold.
- Patient switch tidak memiliki close/Escape/focus-return contract.
- SOS connection/audio/handler truth tidak lengkap dan direct IDLE route menampilkan false event.

### User yang bergantung pada accessibility

- Positif: headings, labels, status text, skip link, dan focus ring umum cukup baik; tidak ada horizontal overflow.
- Risiko: banyak hit target di bawah 44/48px; tidak ada `aria-current`; OCR fields menghapus focus ring; dialog semantics tidak lengkap.
- Small muted copy 10–13px memberi legibility risk walaupun sebagian raw contrast lolos.
- Small primary-blue links pada tinted surfaces terukur sekitar 4.21–4.38:1.
- OCR menghasilkan tab/scroll order yang panjang sebelum keputusan.

## State dan evidence caveats

- False positives yang dipisahkan: Arial di facsimile dokumen, hidden file input, hidden radio input, dan tiny source-document text. Tiny document text diselesaikan dengan zoom fungsional, bukan merombak tampilan evidence.
- State yang terbukti reachable: Patient check-in error/success, Patient safe fallback/emergency, Patient SOS, upload invalid, OCR pending/confirmed/rejected, Caregiver chat context boundary, SOS active/handled, Patient switch masking, dan Faskes filter.
- State yang belum demonstrable: OCR fallback, SOS conflict, serta Faskes empty/error/stale.
